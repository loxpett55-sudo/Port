# 06 — Платформенные сервисы: Storage, Configuration, Observability, Metrics, Diagnostics

## 1. Storage Runtime

**Ответственность:** единая абстракция хранения. Ни один Runtime не
обращается к БД напрямую — только через порты Storage.

### 1.1 Порты по классам хранилищ

| Порт | Семантика | Типичные адаптеры |
|---|---|---|
| `KVStorePort` | ключ-значение, TTL, CAS | Redis, RocksDB, in-memory |
| `RelationalPort` | транзакционные записи, запросы | PostgreSQL, SQLite |
| `VectorStorePort` | векторный поиск, фильтры | pgvector, Qdrant, LanceDB |
| `GraphStorePort` | узлы/рёбра, traversal | Neo4j, поверх Relational |
| `ObjectStorePort` | блобы, стриминг | S3-класс, файловая система |
| `EventLogPort` | append-only, offset-чтение | NATS JetStream, Kafka, встроенный |

Каждый порт имеет **встроенную реализацию** (SQLite + файлы + in-memory)
— платформа полнофункциональна на одной машине без внешних зависимостей;
продакшн-адаптеры подключаются конфигурацией.

Сквозные обязанности: миграции схем (per-module namespaces), шифрование
at-rest (совместно с Security), квоты и tiering (совместно с Resource),
резервное копирование, мультиарендные namespace-ы.

## 2. Configuration Runtime

**Ответственность:** конфигурация всех модулей после старта ядра.

- Источники: файлы, переменные окружения, секреты (через Security),
  удалённый config-сервис — сливаются по приоритету.
- Каждый модуль объявляет JSON Schema своей конфигурации в манифесте;
  валидация при загрузке и при изменении.
- **Hot-reload:** изменение публикуется событием `config.changed(path)`;
  модули применяют без рестарта, если параметр помечен `reloadable`.
- Версионирование и аудит изменений; окружения (dev/stage/prod) —
  профили.

## 3. Observability Runtime

**Ответственность:** платформа наблюдаема по построению — модуль
получает наблюдаемость бесплатно, публикуя события.

| Сигнал | Реализация |
|---|---|
| Logs | Структурированные (JSON), с traceId/sessionId/agentId; редакция секретов и PII до записи |
| Tracing | Сквозные распределённые трассы (W3C Trace Context в конвертах сообщений): запрос → контекст → инференс → инструменты; экспорт OTLP |
| Events | Event Log доступен для просмотра/replay как сигнал наблюдаемости |
| Health Checks | Агрегация `health()` всех модулей: liveness, readiness, зависимость от внешних сервисов |
| Profiling | Профили CPU/памяти по запросу; для инференса — latency breakdown по этапам конвейера |
| Diagnostics | Интеграция с Diagnostics Runtime (ниже) |
| Alerts | Правила над метриками/событиями → каналы уведомлений (адаптеры: email, webhook, мессенджеры) |

Специфика AI-наблюдаемости: трасса хода агента включает собранный
контекст (с провенансом), запросы/ответы моделей (с редакцией по
политике), вызовы инструментов — «объяснимость» поведения агента является
частным случаем трассировки.

## 4. Metrics Runtime

**Ответственность:** сбор, агрегация, экспорт метрик.

- Модель метрик: counters, gauges, histograms с label-ами
  (module, tenant, agent, model, tool).
- Ключевые доменные метрики: latency инференса (по этапам), токены и
  стоимость (по моделям/агентам/арендаторам), hit-rate кэшей контекста и
  инференса, глубина очередей, точность retrieval (offline-оценки),
  доля отклонённых политиками действий.
- Экспорт: Prometheus/OTLP-адаптеры; агрегаты — источник данных для
  Resource Runtime (оптимизация) и Dashboard.

## 5. Diagnostics Runtime

**Ответственность:** самодиагностика и разбор инцидентов.

- **State dumps:** снимок состояния модуля/актора по запросу
  (санитизированный).
- **Replay-отладка:** воспроизведение цепочки событий из Event Log в
  изолированном окружении — «как агент пришёл к этому действию».
- **Автопроверки:** консистентность индексов знаний, «осиротевшие»
  задачи, застрявшие workflow, расхождения бюджета ресурсов; результаты —
  события `diagnostics.issue.detected`.
- **Инцидент-паки:** сборка архива (трассы + события + конфиг + дампы) по
  инциденту для передачи разработчику — с редакцией секретов.

## 6. Анализ слоя

- **Масштабируемость:** все сервисы слоя — stateless поверх своих
  хранилищ; сигналы наблюдаемости — сэмплируемые потоки.
- **Безопасность:** редакция секретов/PII на входе в логи и трассы;
  доступ к диагностическим данным — через Policy.
- **Расширяемость:** каждый бэкенд (БД, экспортёр метрик, канал алертов)
  — адаптер; встроенные реализации гарантируют работу «из коробки».
